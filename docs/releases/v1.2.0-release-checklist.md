## B. ⚠ 自动检查命中、需人工确认的遗留项

> 下面这些是事实，不是结论。是否可接受请对应负责人判断。

- [ ] **B1. 安装包不再内置 OAuth 凭证（这次的改动）** — 负责人：维护者 / 程序
  - 命中判据：仓库公开，旧打包配置会把 `credentials.json`（含 `client_secret`）打进 dmg / exe。本次已从 `extraResources` 移除，产物中扫描不到该文件和 secret。
  - 影响：**所有从 1.1.3 升级的人，首次启动都会弹窗要求选择 `credentials.json`**。需要确认团队拿到这个文件的渠道（wiki / 群文件），并在发布通知里写明。
  - 为什么我不下结论：分发渠道和告知方式是团队流程，不是代码问题。

- [ ] **B2. 1.1.3 没有应用内更新能力** — 负责人：维护者
  - 1.1.3 用户不会收到任何提示，必须手动下载安装 1.2.0；之后的版本才能在 App 内更新。需要在群里发一次通知。

- [ ] **B3. 只在本机 Apple 芯片 Mac 上实际运行过** — 负责人：QA
  - `CSM-Setup-1.2.0-x64.exe` 是在 Apple 芯片 Mac 上交叉打包的，校验通过，但**没有在 Windows 上启动过**。
  - 发布后已按决定从 Release 移除 Intel（x64）dmg，macOS 只提供 Apple 芯片版本，以后也不再打 Intel 包。

- [ ] **B4. Windows 应用内「重启并覆盖安装」流程没有端到端验证** — 负责人：QA / 程序
  - 单元测试用模拟对象覆盖了，真实流程要等出下一个版本（如 1.2.1）后，用装好的 1.2.0 点更新才能验证。建议下个版本发布前专门测这一项。

- [ ] **B5. 安装包未签名** — 负责人：维护者（知悉即可）
  - macOS 首次打开要右键 → 打开；Windows 会出现 SmartScreen 提示。更新说明里已写操作方法。

- [ ] **B6. GitHub API 未认证限流 60 次 / 小时 / IP** — 负责人：程序（知悉即可）
  - 办公室共用出口 IP 时可能被限流，代码会自动改读 `releases.atom` 继续检测（已有单测覆盖），一般不影响使用。
