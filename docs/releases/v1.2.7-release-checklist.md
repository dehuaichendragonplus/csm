## B. ⚠ 自动检查命中、需人工确认的遗留项

- [ ] **B1. 「保存到云端」没有端到端实测** — 负责人：维护者
  - 命中判据：测试只在禁用上传的沙盒项目里跑了「保存本地」；「保存到云端」会真实写入共享的 Google 表格，没有在真实表上点过。
  - 它复用了 1.2.6 的上传核心（冲突检测、保留公式写入、写回源表确认），但「在打开时的云端导出版本上应用编辑再上传」这条新路径没有跑过。
  - 为什么我不下结论：没有可随意写入的测试表。建议发布后先用一张测试表试一次。
- [ ] **B2. 插入 / 删除行后的附属区域** — 负责人：维护者
  - 写回本地时，有合并单元格的表会直接拒绝插入 / 删除行；但**条件格式 / 数据验证 / 超链接 / 筛选区域**不会跟着行移动，只在保存结果里提示一句。配置表一般没有这些，是否可接受由维护者判断。
- [ ] **B3. 新写入的单元格类型靠推断** — 负责人：维护者
  - 改写原有单元格时沿用原类型（文本 / 数值）；新插入的单元格按同列上方最近的单元格推断。实测 FoodFlow1 WeeklyChallenge 复制 9 行后用 `localBuilder.js` 导出，`arraynumber` 列结果正确。没有覆盖所有项目的表。
- [ ] **B4. 1.2.4 / 1.2.6 遗留项仍未闭环** — 负责人：维护者 / 多语言负责人
  - App 内「写回源表」确认弹窗文案未经评审
  - Intel Mac 包为交叉打包，未在 Intel 实机启动
  - 1.2.6 的 B2（升级后首次刷新读公式的限额问题）仍需观察
