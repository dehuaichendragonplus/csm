## B. ⚠ 自动检查命中、需人工确认的遗留项

- [ ] **B1. 「新增列 / 删除列」不是本轮发版负责人写的，原作者还没确认完工** — 负责人：维护者
  - 命中判据：发版时 `lib/xlsx-diff.js` 和 `test/xlsx-diff.test.js` 是另一个会话没提交的改动；它的界面部分被 `304045d` 误一起提交了。维护者决定一起发，后端已单独提交。
  - 为什么我不下结论：只核过单测和代码里的判空，没在 App 里打开一张真的新增了列的表看效果，也没有原作者确认。
- [ ] **B2. 升级后首次刷新的影响** — 负责人：维护者
  - 镜像表的同步记录之前只记了自身时间，升级后第一次刷新会显示「有更新」，再经内容核对转回「已同步」或提示下载。实测 FoodFlow1 的 I18n：显示「有更新」→ 内容核对一致 → 「已同步」，符合预期。
  - 首次刷新会对每张表用 Sheets API 读一次公式（实测 FoodFlow1 共 22 张表，一轮刷新内全部读完）。表很多的项目（80 张以上）可能碰到 Sheets 每分钟的读取限额，要两次刷新才识别完。是否可接受由维护者判断。
- [ ] **B3. 1.2.4 遗留项仍未闭环** — 负责人：维护者 / 多语言负责人
  - App 内「写回源表」确认弹窗文案未经评审
  - Intel Mac 包为交叉打包，未在 Intel 实机启动
- [ ] **B4. 提交历史说明** — 负责人：维护者
  - `304045d`（镜像表修复）里混入了「新增列」的界面改动（`public/panels.js`、`public/style.css` 的列标记部分），提交说明里没写。已推送，未改写历史。
